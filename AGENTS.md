# docling-scheduler — Agent Guide

`python -m docling_scheduler [--port 8765]` runs a FastAPI app on loopback only. It launches [docling-agent](https://github.com/mcaimi/docling-agent) runs as Podman containers (one per shard) and monitors them through MLflow and Podman. It also serves a built [docling-ui](https://github.com/mcaimi/docling-ui) from `SCHEDULER_WEB_DIR` and prints a `/#token=…` URL.

## Boundary with the agent

- **Never import agent code**, not even in tests. The only shared artifact is `src/docling_scheduler/settings-schema.json`, generated by `python -m src.docling_agent --print-settings-schema` in the agent repo and vendored here as-is (don't hand-edit it).
- `contract.py` loads it: `SettingSpec`, `SETTINGS_SPEC`, `SETTINGS_BY_KEY`, `DOCUMENT_GLOBS`, `settings_from_mapping` (env → values, same rules as the agent's loader), and `settings_schema()` (the UI form view). Sensitive settings have no default in the contract. `dynamic_default` names map to callables in `_DYNAMIC_DEFAULTS`, and a callable default is never rendered into a container unless set explicitly. An unsupported `schema_version` fails at import.
- Podman is the only executor. Shards always run in containers: loopback endpoints are rewritten to `host.containers.internal`, and embedded Chroma / Milvus Lite are rejected (they'd be lost with the container).
- Document sources follow the agent's `source_backend`. With `local`, `target.host_folder` is required and mounted read-only at `/data/in`. With `s3`, nothing is mounted and pre-flight lists the bucket from the host (`discovery.list_s3_documents`, using the agent's listing rules) to get the count and shard plan. A host `s3_ca_bundle` is mounted read-only at `/data/s3-ca-bundle.pem`. Settings that depend on `source_backend` (`s3_*`, including `AWS_*` fallbacks from the scheduler's env) are rendered only for that backend.

## Modules (`src/docling_scheduler/`)

| Module | Role |
|--------|------|
| `config.py` | `SchedulerConfig.from_env()`: the `SCHEDULER_*` vars (MLflow URI, DB path, envfile, image allowlist, mount roots, token, allowed hosts/origins, reconcile interval, web dir) |
| `contract.py` | Vendored agent settings contract (see above) |
| `settings_io.py` | `.env` defaults without touching `os.environ`, form-value coercion against the contract, `MANAGED_KEYS` (set only by the scheduler), loopback → `host.containers.internal` rewrite, settings → `(env, secret_env)` |
| `discovery.py` | Document count and shard plan for pre-flight (contract globs; sorted, `paths[i::N]`), local folders and S3 (boto3) |
| `preflight.py` | `run_preflight`: target, settings, document source (host folder or S3 listing), vector store, MLflow reachability and runtime checks; renders launch inputs and a redacted preview |
| `executors/` | `Executor` protocol; `PodmanExecutor` (podman-py: per-run secrets as env, read-only `/data/in` and file mounts, `cap_drop=ALL`, labels `docling-agent/*`) |
| `mlflow_monitor.py` | Parent runs, shard roll-ups and history, merged `error_reports.json`, per-document rows from traces (discovery-order cursor, not timestamps) |
| `reconcile.py` | Pure rules: merged status; RUNNING child runs of dead/superseded shards → FAILED, cancel → KILLED, parent closed when all shards are terminal |
| `service.py` / `api.py` | Launch, refresh/reconcile, cancel, retry failed shards, delete; REST + SSE logs, bearer token, Host/Origin checks, static UI |
| `registry.py` | SQLite metadata only (never secrets) |

## Commands

- `uv sync --extra dev`, then `uv run pytest`. The tests use `tests/unit/fakes.py` (executor, Podman client and S3 client doubles); there's no end-to-end suite, so real runs are tested manually under Podman.
